# PowerPointスライドマスタ ベストプラクティス

> **このドキュメントの目的**：将来Aisunia用または別のPowerPointテンプレート（.potx）を作るとき、ゼロから読めば最適な作り方で進められるよう、原則・落とし穴・固有設計をまとめた再現用ガイド。
>
> **きっかけ**：2026-05-07、当初「親マスタ真っ白＋全装飾を子に直書き」の手順で進めとったが、これは継承を活かさん作り方であることが判明。Brandwares／Microsoft／プレゼンデザインの3情報源で根拠を取り直し、本ドキュメントに集約。

---

## 1. PowerPointスライドマスタの階層構造

```
Theme（テーマ：色・フォント）
  └─ Slide Master（親マスタ：1つだけが原則）
        ├─ Layout 1（子レイアウト）
        ├─ Layout 2
        └─ Layout N
              └─ Slide（実際のスライド：レイアウトを継承）
```

**継承の流れ**：上位の設定は自動的に下位に流れる。テーマで決めた色・フォントは親マスタへ継承され、親マスタの書式は全子レイアウトへ継承され、子レイアウトの書式は実スライドに反映される。

**鉄則**：親マスタは**1つ**にする。複数マスタは保守困難で「problem decks」を生む。

---

## 2. 親マスタに置くべきもの／置くべきでないもの

### 置くべき（YES）
| 要素 | 理由 |
|------|------|
| テーマ色（accent1〜6, hlink等） | 全スライドで色の統一 |
| テーマフォント（日本語・英数字） | フォント変更の一元管理 |
| **全プレースホルダ**（タイトル・本文・日付・フッター・スライド番号） | 削除禁止。レガシースライド更新時に必要。書式の継承元になる |
| 箇条書き（bullet scheme）の書式 | レイアウトに自動継承される |
| **全スライドで共通する**装飾要素（例：すべてのスライドに同じロゴが出る運用ならロゴ） | 一元管理できる |

### 置くべきでない（NO）
| 要素 | 理由 |
|------|------|
| 一部レイアウトでしか使わない装飾図形 | **PowerPoint仕様上、親マスタに置いた図形を子レイアウトで個別非表示にできない**。「背景グラフィック非表示」設定はテーマ背景には効くが、マスタに直置きした図形には効かない |
| レイアウト固有のデザイン要素 | 各レイアウトで別個に置く |

---

## 3. 子レイアウトに置くべきもの／置くべきでないもの

### 置くべき（YES）
- そのレイアウト**固有**の装飾図形・テキスト
- 親マスタのプレースホルダの**位置・サイズ・書式の上書き**（必要なら）

### 置くべきでない（NO）
- 親マスタですでに継承される共通要素を再度置く（継承が壊れる原因）

### プレースホルダの書式上書き
- 子レイアウトでプレースホルダの位置・フォント・色を変更しても、**親マスタの該当書式から継承を受けつつ上書きできる**
- ただし「親マスタを完成させる前に子レイアウトで上書きしてしまう」と、その後の親マスタの変更が**反映されなくなる**（継承が切れる）

---

## 4. 編集順序の鉄則：マスタ完成 → レイアウト

> **"Don't touch a Slide Layout until the Slide Master is complete!"**（Brandwares）

順序を守らんと何が起こるか：
- 例：レイアウトAで赤色の箇条書きを設定 → その後、親マスタで青色の箇条書きを設定
- 期待：レイアウトAも青色になる
- 実際：**レイアウトAは赤色のまま**。子で先に書式を上書きした時点で、その項目の継承は切れる
- 結果：以降は親マスタを変えても、レイアウトA側の同項目は手動で更新する必要がある

### 推奨順序
1. スライドサイズ設定
2. テーマ色・テーマフォント・グリッド・ガイド設定
3. 不要なデフォルトレイアウトを削除
4. **親マスタ**：プレースホルダの位置・書式・全スライド共通要素を完成させる
5. **子レイアウト**：レイアウト固有の要素を追加。必要ならプレースホルダ書式を上書き
6. マスタ表示を閉じる
7. .potx で保存

---

## 5. プレースホルダ vs 通常テキストボックス

| 種類 | いつ使う | メリット | デメリット |
|------|----------|----------|------------|
| **プレースホルダ** | タイトル・本文・フッターなど「スライドごとに中身が変わる」要素 | 本番運用で「タイトル」欄が機能する／アウトライン表示に乗る／「ヘッダーとフッター」ダイアログで一括変更できる／継承が効く | 配置の自由度はテキストボックスよりやや低い |
| **通常テキストボックス** | 装飾的な固定文言・スライドごとに変わらない要素 | 自由配置 | 上記メリットが効かない |

### Aisuniaでの判断例
- **プレースホルダ化**：レイアウトのタイトル（「目次」「コンテンツ」など毎回変わる）／フッター（屋号変更があれば一括変更したい）／スライド番号（自動採番）
- **通常テキストボックスでもOK**：「Aisunia All rights reserved.」（屋号は変わらないので固定でもよい — ただしフッタープレースホルダで管理する方が拡張性は高い）

## 6. 「レイアウトの複製」で類似レイアウトを展開

共通装飾を持つ複数レイアウトを作るとき、**コピペ**ではなく**「レイアウトの複製」**を使う。

### 操作手順
1. スライドマスター表示で、左サイドバーから複製元のレイアウトを右クリック
2. 「**レイアウトの複製**」を選択
3. 複製されたレイアウトの中身（タイトル文言・本文）だけ書き換える

### コピペとの違い
- コピペ：図形を1つずつ選択して貼り付け。位置ズレが起きやすい
- 複製：レイアウト構造ごと複製されるので、再現性が高く保守も楽

---

## 7. PowerPointの仕様・制約（落とし穴）

### 7-1. 親マスタの図形は子レイアウトで個別非表示にできない
- 「**背景グラフィック非表示**」設定は**テーマの背景**には効くが、親マスタに直置きした**図形**には効かない
- 結論：「過半数のレイアウトで使う」装飾でも、ヘッダー無しレイアウトが少数ある場合は親マスタに置かない方が無難

### 7-2. .potx を編集するときは「ファイル→開く→参照」で開く
- ダブルクリックで開くと「新規プレゼン作成」になり、テンプレ自体が編集されない
- タイトルバーが「**Aisunia_Template - PowerPoint**」になっとるか必ず確認

### 7-3. 親マスタ以外を全削除しても、1つだけ自動再生成される
- PowerPoint仕様。無視してそのまま進める。最後にもう一度削除を試みればよい

### 7-4. デフォルトレイアウト名の扱い
- Brandwaresは「Microsoft標準のレイアウト名（タイトルスライド・タイトルとコンテンツ等）はそのまま残す」を推奨
- 名前を変えると、別テンプレートからスライドをインポートする際に「同じレイアウトと認識されず重複が増える」

### 7-5. 複数マスタは作らない
- 複数Slide Masterを持つ.pptxは保守困難。1マスタ＋複数レイアウトに統一

## 8. Aisunia固有の構造設計（6レイアウト）

### 構造
```
親マスタ
  ├─ タイトルプレースホルダ（位置・フォント・色を継承定義）
  ├─ フッタープレースホルダ（既定値「Aisunia All rights reserved.」）
  └─ スライド番号プレースホルダ（書式定義）

子レイアウト 6種
  1. 表紙           ─ 独立デザイン（紺背景・赤バー・タイトル中央寄せ）
                     親プレースホルダ位置を上書き／フッター・番号を非表示
  2. 目次           ─ 装飾あり（紺帯ヘッダー＋フッター付き）★ベース
  3. コンテンツ     ─ 目次を「複製」して中身入替
  4. セクション区切り ─ 独立デザイン（左半分紺・右半分白）
                     フッター・番号を非表示
  5. 2カラム比較    ─ 目次を「複製」して中身入替
  6. エンド         ─ 独立デザイン（紺背景・締めメッセージ）
                     フッター・番号を非表示
```

### なぜこの設計か（Aisunia固有の判断理由）
- 6レイアウトのうち**ヘッダー・フッターありが3つ／なしが3つ**でちょうど半々
- 親マスタに紺帯ヘッダー等を置くと、「なし」3レイアウトで邪魔になり、しかもPowerPoint仕様上、子で個別非表示できない（→ 7-1）
- そこで親マスタには**プレースホルダ（書式継承の素）だけ**を置き、装飾は装飾あり3レイアウトに直接配置
- 装飾あり3レイアウトのうち「目次」だけ手で完成させ、コンテンツ・2カラム比較は**複製**で展開

### カラー
- 赤 `#BC002D` / 紺 `#1A2B4A` / スレートブルー `#5C7A99`
- グレー背景 `#F4F6F8` / ライトグレー（区切り線）`#CCCCCC` / ライトブルー（フッター文字）`#AABBCC`
- 詳細：`docs/design-system.md` 参照

### フォント
- 日本語：BIZ UDPゴシック
- 英数字：BIZ UDPGothic

### スライドサイズ
- 33.87cm × 19.05cm（標準16:9）

## 9. 自動化スクリプトの位置づけ

`brand/slides/tools/` 配下のPythonスクリプトは、**自動化できる部分を自動化する**ためのもの。

| スクリプト | 役割 | 出力 |
|------------|------|------|
| `create_potx_base.py` | スライドサイズ・テーマ色・フォントを設定した空テンプレ.potxを生成 | `brand/slides/outputs/Aisunia_Template.potx` |
| `create_pptx_template.py` | 全6レイアウトを盛り込んだサンプル.pptxを生成（参考用） | `brand/slides/outputs/Aisunia_PowerPoint_Template.pptx` |
| `create_pptx_variants.py` | カラーバリアント7種の.pptxを生成（A〜G案） | `brand/slides/outputs/Aisunia_PowerPoint_*.pptx` |

**手作業との分担（B案ハイブリッド）**：
- 自動化：テーマ色・フォント・スライドサイズ・.potx化
- 手作業：親マスタのプレースホルダ整備＋子レイアウト6つの装飾配置

## 10. やってはいけないこと（落とし穴総まとめ）

1. ❌ 親マスタを真っ白にして、全装飾を子レイアウトにコピペで配置する
   → 屋号変更等のとき、全レイアウトを手で修正する必要が出る。継承を活かさず保守コスト倍
2. ❌ レイアウトを先に編集してから親マスタを完成させる
   → 継承が切れて、親マスタを変えても子に反映されなくなる
3. ❌ タイトル・フッターを通常テキストボックスで置く
   → 本番運用でタイトル欄が機能しない／アウトライン表示に乗らない
4. ❌ 複数Slide Masterを作る
   → 保守困難。1マスタに統一
5. ❌ 親マスタからデフォルトプレースホルダを削除
   → レガシースライド更新時に問題が出る
6. ❌ 「過半数のレイアウトで使う」装飾を親マスタに置く（残りのレイアウトで非表示にしたい場合）
   → PowerPoint仕様上、子で個別非表示できない
7. ❌ .potxをダブルクリックで開く
   → 新規プレゼン作成になり、テンプレ自体が編集されない
8. ❌ 「スライドごとに内容が変わる」要素（日付・セクション名・締め文言など）を通常テキストボックスで置く
   → スライドマスタ側では編集できても、実際のプレゼン作成時にスライド上で編集できない
   → 毎回変わる情報はプレースホルダ、毎回固定の情報はテキストボックス、と使い分けること
